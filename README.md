# python-webhook-order-processor
# Python Webhook Order Processor

A lightweight Python webhook application built with Flask and tested in Google Colab. It receives mock order events through HTTP POST requests, validates incoming JSON data, calculates order totals, and logs successfully processed orders.

The project demonstrates how webhook-based integrations work and how incoming business events can be processed programmatically.

## Features

- **Webhook endpoint:** Receives order data through an HTTP POST request.
- **JSON validation:** Checks required fields, item structure, prices, and quantities.
- **Request authentication:** Uses a shared secret sent through the `X-Webhook-Secret` HTTP header.
- **Order calculations:** Calculates order totals using Python's `Decimal` module.
- **Event logging:** Records successfully processed orders in a JSON Lines (`.jsonl`) file.
- **Health check:** Provides an endpoint to check whether the server is running.
- **Cloud-based development:** Runs in Google Colab without requiring a local Python installation.
- **Public testing:** Uses ngrok to expose the temporary Flask server to external HTTP requests.

## Technology Stack

- Python
- Flask
- Google Colab
- ngrok / pyngrok
- Requests
- JSON and JSONL

## How It Works

1. A client sends an order payload to the webhook endpoint.
2. The server checks the shared secret to authenticate the request.
3. The incoming JSON payload is validated.
4. The server calculates the total order value.
5. Successfully processed orders are appended to `orders.jsonl`.
6. The server returns a JSON response containing the processing result.

### Workflow


## Getting Started

### Prerequisites

You need:

- A Google account to use Google Colab.
- An ngrok account and authtoken for temporary public access.
- The project notebook uploaded to your Google Drive or GitHub repository.

No local Python installation is required when running the notebook in Google Colab.

### 1. Open the notebook

Open the `webhook_colab.ipynb` notebook in Google Colab.

### 2. Install dependencies

Run the installation cell:

```python
!pip -q install flask pyngrok requests
```

### 3. Start the Flask server

Run the notebook cell that initializes the Flask application.

When prompted, enter a webhook secret containing at least 16 characters. Keep this secret private.

The application exposes these endpoints:

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Checks server status |
| POST | `/webhook/orders` | Receives and processes orders |

### 4. Configure ngrok

Obtain your authtoken from the [ngrok dashboard](https://dashboard.ngrok.com/get-started/your-authtoken).

Run the notebook's tunnel setup cell and enter the authtoken when prompted. The notebook will generate a temporary public URL.

Your webhook endpoint will have this format:

```text
https://YOUR-NGROK-DOMAIN/webhook/orders
```

Use the actual URL generated by ngrok.

### 5. Send a test order

The following example sends a mock order to the webhook:

```python
import requests

payload = {
    "order_id": "ORD-1001",
    "customer": "Asha",
    "items": [
        {
            "name": "Headphones",
            "price": 1999,
            "quantity": 1
        },
        {
            "name": "Cable",
            "price": 299,
            "quantity": 2
        }
    ]
}

response = requests.post(
    PUBLIC_URL + "/webhook/orders",
    json=payload,
    headers={
        "X-Webhook-Secret": WEBHOOK_SECRET
    },
    timeout=30
)

print("Status:", response.status_code)
print("Response:", response.json())
```

### Expected Result

```json
{
  "order_id": "ORD-1001",
  "customer": "Asha",
  "item_count": 2,
  "order_total": "2597.00",
  "status": "processed"
}
```

The response also includes a `received_at` timestamp, which is omitted above for readability.

The calculated total is 1999 + (299 × 2) = 2597.

### 6. Inspect the logs

Successfully processed orders are appended to:

```text
/content/orders.jsonl
```

Each line represents one processed order event in JSON format.

The file is stored in the active Colab runtime and is not automatically preserved after the runtime is deleted.

## Limitations

- The webhook is a demonstration project, not a production order-processing system.
- The Flask server and ngrok URL are temporary and depend on the Colab runtime remaining active.
- Log files and in-memory configuration can be lost when the runtime terminates.
- The project does not currently implement persistent database storage, duplicate-order prevention, retry handling, or a production-grade deployment architecture.
- A shared-secret header provides basic authentication but does not replace a complete production security strategy.
- Currency calculations are demonstrated using decimal arithmetic; the project does not implement a complete payment or tax system.

## Security Notes

- Never commit ngrok authtokens or webhook secrets to GitHub.
- Enter secrets through runtime prompts rather than hardcoding them in notebook cells.
- Do not include real customer information in sample payloads or screenshots.
- Revoke and regenerate any token accidentally exposed in a public repository or shared conversation.
- Use HTTPS and appropriate authentication when exposing a webhook publicly.
